# Ontario nearby reported well records

`ontarioWellRecords` adds reported well work near a suitable caller-supplied or independently resolved Ontario point. It helps a realtor ask for the actual subject-well records, maintenance and abandonment history, water tests and performance evidence. A nearby record does not identify which well serves the property.

The original MECP [Well Records catalogue](https://data.ontario.ca/dataset/well-records) explicitly refers to the [official well map](https://www.ontario.ca/page/map-well-records). The map offers the original Ontario-hosted app, whose audited public bundle identifies MOE/Wells/MapServer. Only child 0, Wells, is searched and counted. Child 1, Wells_Report, is a duplicate report representation and is excluded. The October 3, 2026 original count query returned **988,388 published well-report rows**, not distinct properties, current operating wells or imported database records.

Before records or counts, the adapter verifies the exact active catalogue ID/publisher, Ontario licence referral, audited 2026a shapefile and metadata-resource bindings, complete current Open Government Licence – Ontario text, original map iframe/app revision/bundle fingerprint and live typed point-child schema. A changed revision needs a new audit. All URLs are fixed; no caller URL, authentication, configuration key, signed request or arbitrary redirect is followed. Responses have an eight-second per-read deadline, a one-MB bound and one-hour cache.

The live query has a 500-metre distance scope and requests at most 51 records ordered by OBJECTID. Up to 50 records within 500 metres of the returned map geometry are shown, sorted by distance. A capped/transfer-limited query is explicitly incomplete and does not establish the nearest 50 records or full history. Malformed or duplicate IDs, missing/wrong typed fields and invalid geometry/datum fail closed. Street-interpolated, ambiguous, missing or out-of-scope coordinates are skipped. Ontario province context is required; the numeric bounds are an additional sanity check, not a cadastral or legal provincial-boundary determination.

Whitelisted facts are well/bore-hole IDs, raw reported completion/received dates and completion year, reported final status/use, reported depth in metres and source county/municipality/geographic-township labels. Approximate map coordinates and distances retain their own labels. Source errors and negative/sentinel observations are not converted into measured current conditions. Contractor, commissioning-person, street/legal-description and original-PDF path fields are excluded; individual well PDFs are not fetched or redistributed.

The original 2026a metadata was read and both rendered pages inspected. It describes submitted records for water-supply wells, test holes and dewatering wells, warns of inherited location/other errors and data-entry errors, and identifies commissioning-person information as confidential. It explicitly shares the information under the Ontario licence. No inference is made about current operation, water quality, potability, yield, contamination or actual municipal/private servicing. No match does not prove no well.

Dates stay separate: catalogue metadata modified August 13, 2026; shapefile resource publication July 31, 2026; download range January 1, 1899–June 30, 2026; metadata document stamp June 2, 2026 and preparation July 8, 2026. These dates do not date the live map observations. The live service build string is also not an observation date: `sourceUpdatedAt` and `liveServiceObservationDate` remain unknown. Runtime coverage records the then-observed catalogue/resource labels separately.

The API, HTML report, pre-showing briefing, document requests, OpenAPI, coverage and exact skill/document mirror carry this context. Homies continues to create the detailed report with native `fs_write`/`share_artifact`; its one-click starter stays unchanged. This shared provincial baseline does not complete any municipality's permit, current zoning, planning, heritage, unit or constraint audit.
