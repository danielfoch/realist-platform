# Property forensics and deep research

Starter prompt: **Create a property forensics report for me.**

Use the property already in the conversation, saved workflow or listing. If its civic address and municipality are missing, ask one simple question: “Which property would you like me to research?” Infer province when unambiguous. The user does not need a key, URL, edited placeholder or setup. Create the report as the default deliverable; do not stop at a chat summary or ask whether to create it.

## Fetch the evidence

GET https://realist-lean.vercel.app/api/property with the address query parameter set to the street address, municipality and province using the HTTP client's query encoder. Optional city, province, lat and lng (both coordinates together). Do not invent coordinates. Use verified property coordinates only when available. One real example is https://realist-lean.vercel.app/api/property?address=16%20Soho%20St%2C%20Toronto%2C%20ON .

Read layers, available, missing, brief and followUpQuestions before describing the property. Save the complete response as a workspace JSON evidence file. Capture lookup time and the submitted address, resolved address, matching method and coordinate accuracy. Keep all returned records, histories, source links, licences, attributions, sourceUpdatedAt, importedAt, retrievedAt and truncation flags. A fetch/import today does not make an observation current. Unknown dates stay unknown.

Only status=available establishes returned evidence. Distinguish no_match, not_supported, not_loaded, unavailable, ambiguous and skipped in the report. No-match does not prove the absence of a permit, condition, designation or registration. Do not guess an ambiguous address or condominium unit. Unit-specific requests return 422; explain building-level scope and ask for a civic building address if that meets the user's purpose. Do not silently strip the unit number.

## Build a useful report for the realtor

Start with a short pre-showing briefing: property identity, key supported findings, items to verify before showing or offering, seller questions and documents to request. Use brief as a starting structure and prioritize the actual returned evidence. Document requests are recommendations; do not say documents are missing unless the supplied file set establishes that. If a listing or seller documents are already available, compare their specific claims with the dated records. Separate confirmed conflicts, possible date/scope differences and unknowns. If no listing is supplied, label comparison “Not assessed — listing not supplied”; finish the report without blocking on a listing upload.

Follow with a detailed evidence appendix. Include every returned layer, even unsupported or failed ones, and all its available fields and returned records: address-register provenance; municipal assessment and annual history where available; parcel identifier and lot area; GIS zoning and ward; permits and variance decisions with published dates/status; nearby development; rental-building features and dated evaluations; registered additional units; heritage; conservation screens; and neighbourhood census context. Translate technical field labels into plain English without changing values. Currency is CAD. Preserve each published area unit; if a source-specific area field has no verified unit, leave its unit unknown. Keep yearly assessments separate from asking price, sold price and market value. Census income/dwelling values describe the area, not this household/property. Never fill Ontario MPAC values, MLS history, owner contacts or an AVM from inference.

## Create and share the report in the Homies harness

Use the harness's real artifact tools. At the top-level Homies chat, first delegate the complete report job to ONE worker using invoke_skill_tool(skill="manage-agents", tool="spawn", args={"tasks":[{"name":"property-forensics","prompt":the complete property-specific report instructions}]}). Include the address, evidence/workspace paths, listing context and existing artifact ID when revising. The worker owns the whole fetch → design → write → review → share flow and must return the actual share URL. The design review tool requires a worker/sub-agent; do not attempt it from the parent chat. Relay the worker's returned report link to the user. Use the tasks array with name and prompt fields; the worker has no chat history, so its prompt must include the relevant context and this full report workflow. A static, printable, self-contained HTML report is the default; use JSX only if interaction materially improves the report. Inline all evidence and styles; the report must not depend on authenticated fetches or imports in the artifact iframe.

1. Load saved brand once per session with invoke_skill_tool(skill="design", tool="tokens", args={}).
2. Request a report brief with invoke_skill_tool(skill="design", tool="brief", args={"kind":"static-html","surface":"marketing"}). Use kind="react-artifact" if writing JSX. Before writing code, state exactly four short lines in chat: Visual thesis, Content arc, Interaction thesis, Direction. Follow the returned brand/design direction.
3. Use fs_write to save the evidence JSON and complete report to workspace-relative paths, for example reports/property-forensics-soho/report.html. Use a stable property-specific path; do not expose private client documents in the public report without explicit authorization. Public property evidence can be shared as requested.
4. Invoke invoke_skill_tool(skill="design", tool="review", args={"path":reportPath}). Fix blockers and warnings, then review again until passing=true. Do not bypass a failed publish gate.
5. Call share_artifact with {"path":reportPath,"title":a short human title such as "Property Forensics — 16 Soho Street"}. Record the returned artifact_id and URL. The share link is public to anyone with it; do not claim it is private or expiring.
6. Reply with the actual returned URL as a clear clickable “Open property forensics report” link and a few useful findings/gaps. Never invent an artifacts URL or claim sharing succeeded if the tool failed. Revise an existing report using update_artifact with {"artifact_id":existingId,"path":reportPath,"title":title} to preserve its link. A saved artifact is a dated snapshot; re-fetch evidence before a requested refresh.

If outside Homies or the native artifact tools are unavailable, provide the printable fallback at https://realist-lean.vercel.app/api/property/report using the same encoded query, plus the available evidence summary. Label it as the Realist report link, not a Homies artifact. Never use an imaginary link-creation tool. No CRM changes or contacting anyone are authorized by this research skill.
